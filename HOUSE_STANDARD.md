# House standard

The bar every repo on the account must clear. Checked by `repo_doctor.py`.

## README.md

Structure follows the template Pratham picked, with three sections dropped
on purpose: **Contribute**, **Credits**, and **License**. GitHub already
renders those natively on the repo page (contributors list, license badge
on the right), so repeating them in the README is noise.

### Required (flagged as missing)

- Title: a real heading at the top, not just the repo name by default
- Description: one or two honest lines under the title saying what it is
- Motivation: why the project exists
- Tech/framework used: what it is built with
- Features: what makes it stand out
- Installation: step by step, copy pasteable
- How to use: step by step guide

### Recommended (flagged as warnings)

- Build status, code style, screenshots, code example, API reference, tests

## About box (the right-side layout)

- Description: filled in, one line
- Website: link set (live demo, docs, or product page)
- Topics/tags: at least one

Releases, deployments, used-by, contributors, and languages are rendered
by GitHub automatically. Nothing to do there.

## License

A LICENSE file must exist in the repo root so the license shows on the
repo page.
